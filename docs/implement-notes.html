Viết lại README chuyên nghiệp và gỡ phase roadmap files

Phạm vi
Cập nhật tài liệu chính của repo, cấu trúc tài liệu root, và bản đồ kiến trúc phiên sau.
Thay đổi
Viết lại README.md với mô tả sản phẩm, screenshot demo, Mermaid diagram cho kiến trúc hệ thống, luồng hoạt động, database/storage, deploy architecture, API surface, setup, verification, roadmap và documentation map. Xóa các file phase*.md khỏi root vì roadmap đã được gom vào README và docs hiện hành.
Lý do
README cũ còn thiên về milestone nội bộ và liệt kê phase files. Bản mới phù hợp hơn cho người xem repo, nhà tuyển dụng hoặc reviewer kỹ thuật vì trình bày rõ product value, kiến trúc, dữ liệu, vận hành và kiểm thử.
Tác động
Người mới vào repo có thể hiểu nhanh hệ thống từ README mà không cần đọc các file phase rời rạc. docs/ARCHITECTURE.md được cập nhật để không còn tham chiếu sai tới phase*.md.
Kiểm chứng
Kiểm tra git status trước khi sửa, xác nhận danh sách phase files, cập nhật tài liệu liên quan và rà lại các tham chiếu phase*.md còn sót bằng ripgrep.
Review tiếp
Khi có URL deploy thật, cập nhật README phần Deployment bằng production frontend/backend URL chính thức.
2026-07-02 15:08:07 +07:00 Người note: KhanhGiauTen Loại: Quy trình dài hạn

Thiết lập luật đọc kiến trúc và ghi note xuyên phiên

Phạm vi
Thêm rule project cho agent, tạo tài liệu kiến trúc sống, và khởi tạo nhật ký triển khai HTML.
Thay đổi
Tạo AGENTS.md, .github/copilot-instructions.md, docs/ARCHITECTURE.md, và docs/implement-notes.html. Rule yêu cầu mọi phiên đọc architecture + notes trước khi làm việc, và mọi thay đổi chạm mã nguồn/cấu hình/workflow phải được ghi lại bằng card tiếng Việt mới nhất ở trên cùng.
Lý do
Dự án phục vụ nghiên cứu dài hạn nên cần bộ nhớ bền vững để agent không phải quét toàn bộ repo mỗi phiên, đồng thời lưu lại bối cảnh quyết định khi refactor hoặc mở rộng hệ thống.
Tác động
Các phiên sau có quy trình bắt đầu rõ ràng, tài liệu kiến trúc làm nguồn tham chiếu nhanh, và lịch sử thay đổi có timestamp/người note để hỗ trợ review, merge, và truy vết hiệu quả quyết định.
Kiểm chứng
Kiểm tra nội dung tài liệu và trạng thái git. Đây là thay đổi tài liệu/rule, không yêu cầu chạy test backend/frontend.
Review sau
Sau vài phiên làm việc, đánh giá xem note card có đủ thông tin để phục dựng quyết định không; nếu thiếu, cập nhật template card trong file này và rule tương ứng.

Quy tắc cập nhật

  1. Thêm card mới ngay dưới phần <section class="notes">.
  2. Giữ timestamp ISO trong data-timestamp và timestamp đọc được trong header card.
  3. Luôn dùng tiếng Việt cho nội dung note.
  4. Cập nhật header trang nếu card mới là note mới nhất.

Khi merge conflict

  • Không xóa card hợp lệ từ nhánh khác.
  • Sắp xếp card theo thời gian mới nhất trước.
  • Nếu có note trùng chủ đề, đánh giá hiệu quả thực tế rồi mới hợp nhất nội dung.
  • Ghi thêm card giải thích phương án resolve nếu conflict ảnh hưởng quyết định kỹ thuật.
